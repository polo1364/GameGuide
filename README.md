# GameMaster 遊戲攻略助手

以繁體中文查詢遊戲、生成攻略並進行追問的網頁工具。使用 DeepSeek 生成內容，先讀取核准來源，再用第二次模型請求比對草稿與證據；證據不足的部分會標示「待確認」。

目前應用程式版本為 **4.16.0**；遊戲資料庫版本為 **2.12.0**，共 **1,029 筆**，查核快照日期為 **2026-10-19**。收錄熱門手機、台灣手機與獨立遊戲，也保留部分尚未上市或身分待釐清的條目。收錄優先級不是即時人氣排行榜。

## 主要功能

- 遊戲名稱與別名搜尋、平台提示、具名版本與發行狀態辨識；另有維基百科搜尋補充。
- 簡單查詢、Boss 打法、配裝比較與追問，依問題調整回答結構及目標篇幅。
- 官方來源優先，區分官方維基與次級攻略；逐段顯示來源連結與待確認原因。
- 章節目錄、內容折疊、閱讀設定、手機版表格與攻略收藏。
- Service Worker 快取網站資源；首次成功載入後，可離線開啟已快取的介面。生成攻略與讀取遠端來源仍需連線。

## 本機啟動

需要 **Node.js 20 以上**與現代瀏覽器。執行網站只使用 Node.js 內建模組，沒有建置步驟，也不需要先安裝 npm 套件。

```powershell
git clone https://github.com/polo1364/GameGuide.git
cd GameGuide
node server.cjs
```

開啟 <http://127.0.0.1:14438/>。停止服務時，在終端機按 `Ctrl+C`。

若連接埠已被使用，可指定其他埠號：

```powershell
node server.cjs 14439
```

此時改開啟 <http://127.0.0.1:14439/>。服務僅監聽 `127.0.0.1`，其他裝置無法直接透過區域網路連線。

### 設定 DeepSeek

1. 開啟網站的 API 設定視窗，輸入自己的 DeepSeek API Key 並儲存。
2. 選擇具體遊戲，盡量在問題中提供平台、版本、模式及進度。
3. 點選「生成攻略」，等待來源讀取、生成與內容比對。
4. 閱讀各段來源及「待確認」提示；需要補充時使用追問，也可收藏攻略。

目前程式設定使用 `deepseek-flash`，由瀏覽器直接呼叫 DeepSeek。一次生成或追問最多使用兩次模型請求，會消耗該帳號的 API 額度；請求失敗或重試也應留意實際用量。本專案不提供 API Key，也不會從 `DEEPSEEK_API_KEY` 環境變數讀取金鑰。

## 來源查核如何運作

1. 依遊戲與問題，從 `guide-sources.json` 的專用來源及資料庫中的核准官方網址選擇候選頁面。問題內提供的網址也必須屬於核准網域。
2. 本機 `/api/guide-sources` 端點擷取正文，保留來源、適用範圍及讀取失敗原因；每次最多選取五個來源。
3. DeepSeek 依實際取得的文字生成草稿，再透過第二次請求逐段比對內容。
4. 程式檢查來源 ID 與引文是否能對應正文；未通過的段落隱藏原正文，改顯示待確認原因。查核回應失敗或格式不完整時，不顯示未通過查核的草稿。

若完全沒有可讀來源，會略過第二次比對，將全文標示為待確認，不能視為已查證攻略。

### 覆蓋範圍與限制

- 目前具備專用玩法來源的遊戲是**星露谷物語**與**艾爾登法環**，且僅涵蓋來源設定中的相關主題。其他遊戲會嘗試使用資料庫內的核准官方頁面。
- 商店頁面通常只能支持遊戲介紹或平台資訊，不能證明 Boss 機制、掉落率或配裝數值；遊戲已收錄不代表攻略已有充分證據。
- 來源讀取採核准清單，沒有通用網路搜尋，也不會任意抓取模型產生的網址。要求登入、瀏覽器驗證或僅以 JavaScript 載入正文的頁面可能無法讀取。
- 官方維基仍可能由社群編輯；次級攻略會另外標示。舊版來源不等於現行版本證據，來源衝突或版本無法確認時需保留待確認。
- 引文對應與 AI 比對不能保證每個推論正確。來源快取約五分鐘，平台與發行資料也屬查核快照，並非即時更新。
- 回答篇幅是提示詞中的目標，不是硬性字數上限；必要條件與證據說明可能使內容較長。

## API Key 與本機資料

API Key、設定及收藏儲存在目前瀏覽器的網站儲存空間，使用 IndexedDB，並有 localStorage 備援機制。這不是加密的憑證保管庫；請勿在共享瀏覽器保存私人金鑰，也不要把金鑰寫進程式碼、提交到 Git 或貼進問題中。

金鑰由瀏覽器直接傳送給 DeepSeek，本機來源服務不接收金鑰。問題、對話與來源摘錄會隨生成請求送至 DeepSeek；來源服務也會連線到核准的外部網站。名稱搜尋可能使用維基百科，字型使用 Google Fonts。

不同瀏覽器、`localhost` 與 `127.0.0.1`、不同連接埠均可能使用不同的網站儲存空間。更換網址後看不到原設定或收藏時，請先確認是否回到原本的網址；清除網站資料也會移除本機保存的內容。

## 測試

來源服務測試不需要額外套件：

```powershell
node tests/source-reader.cjs
```

瀏覽器回歸測試需要 Playwright 與 Chromium。專案目前沒有 `package.json`，可在專案根目錄安裝本機測試依賴：

```powershell
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/regression.cjs
```

若環境已提供 Playwright，也可透過 `NODE_PATH` 指向其所在的 `node_modules`。測試會自行啟動測試伺服器，不需先執行 `server.cjs`，也不需真實 API Key。

回歸測試涵蓋資料查核、版本與別名、Markdown 編號與安全連結、查核失敗處理、收藏、離線快取，以及 1440、390、320 像素寬度的介面。一般測試使用模擬 API 回應與已保存的實際生成內容，不會重新呼叫 DeepSeek；畫面測試不等於實體手機驗收。

最近一次程式驗證結果為 **56/56 回歸測試通過**，來源服務測試通過。實際生成與查核紀錄見 [驗證紀錄](tests/deepseek-verified-20261019/audit.json)，最終內容保存在同目錄的 `*-final.json`。測試截圖及部分本機紀錄未納入 Git，因此紀錄內提到的圖片不一定存在於儲存庫中。

## 專案結構

| 路徑 | 用途 |
| --- | --- |
| `index.html` | 網頁樣式、搜尋、生成、查核結果呈現與本機儲存 |
| `games.json` | 遊戲名稱、別名、平台、發行狀態與查核來源 |
| `server.cjs` | 本機靜態網站與來源讀取 API |
| `guide-sources.json` | 核准官方網域、專用來源與適用範圍 |
| `sw.js`、`manifest.json` | 網站快取與 PWA 設定 |
| `tests/regression.cjs` | 瀏覽器與資料回歸測試 |
| `tests/source-reader.cjs` | 來源端點、網路限制與錯誤處理測試 |
| `tests/platform-audit/`、`tests/catalog-expansion-*/` | 歷次查核、擴充與測試使用的資料快照 |
| `tests/deepseek-verified-20261019/` | DeepSeek 實測內容與查核紀錄 |

擴充來源時，應確認作品身分、平台、版本與來源適用範圍，再更新 `guide-sources.json`；不要只因為頁面可開啟，就視為支持所有攻略細節。修改遊戲資料後也應重跑回歸測試。歷史資料快照會被測試引用，請勿當作一般暫存檔刪除。

## 部署與常見問題

**GitHub Pages 可以直接使用完整功能嗎？**

GitHub Pages 只能提供靜態檔案，不能執行 `server.cjs`。介面可以載入，但 `/api/guide-sources` 不存在時，攻略會顯示來源服務無法使用及待確認。要使用完整流程，請依上面的本機啟動方式執行。

**可以直接把目前伺服器公開到網路嗎？**

目前伺服器定位為本機工具，包含 Host／Origin、核准網址、公開 IP、重新導向、回應大小、逾時與請求數限制。尚未提供公網部署的登入或使用者隔離方案；不能只修改監聽位址就當作正式公開服務。

**為什麼找得到遊戲，卻沒有確定的攻略？**

名稱搜尋、平台資料與玩法證據是不同範圍。來源可能沒有相關機制、讀取失敗，或遊戲版本仍有歧義。請先補上具體版本及問題；若仍缺乏證據，保留待確認是預期行為。

**為什麼 API Key 已儲存，生成仍失敗？**

儲存設定不等於已驗證金鑰。請依畫面錯誤檢查金鑰、帳號額度、網路與 DeepSeek 回應；若查核 JSON 不完整或回覆被截斷，程式會隱藏草稿並提示重試。
